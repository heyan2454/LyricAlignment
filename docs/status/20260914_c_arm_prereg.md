# C 臂预注册：字符级 loss 加权（2026-09-14 07:23，早于任何结果）

## 为什么是 C 而不是别的
今晚用测量依次关闭了四条"不重训"的路径，并确认数据路径也走不通：

| 路径 | 实测结论 |
|---|---|
| 同一批 logits 内重排 | ≥2s 失败子集容差内概率质量中位 0.142、**0/9 超过 0.5** ⇒ 不可重排救回 |
| 约束解码（DP） | 域内确实更好（配对 −2.24 ms, z=−5.27）；真歌上替代点证据更高仅 46%/51% ⇒ **只修合法性** |
| 跨窗共识（改变输入） | 配对 **+18.7 ms（z=+9.9）更差** ⇒ 误差是系统性偏差而非噪声 |
| 事后时长校准 | 无收益：all 2.60% → 2.63%、≥2s 10.23% → 10.70%；按熵条件化把 ≥2s 推到 18.60%（更差）⇒ 关闭。<br>（先前引用的 37.67% 是我的钳位伪影，已更正） |
| 新数据补长音暴露 | GTSinger 全库仅 300 个 ≥1s / 70 个 ≥2s；MIR-1K 无字符级边界 ⇒ **无供给** |

条目级上采样（B 臂）的暴露份额增益**饱和于 ×2.58**（含长字符的条目占 38.8% 的字符），
所以它是弱仪器。字符级 loss 加权不受这个饱和限制：**它是唯一还能在不加数据的前提下
强化"长音暴露"机制的手段**，代码（`src/lyricalign/training/timestamp_loss.py`）与等价性测试已完成。

## 假设
H-C：长字符（尤其 ≥1.5 s）失败源于训练时对**非常见时长**的监督压力不足；
把这两个槽位的 CE 权重提高，会显著降低长字符超差率，并把失败子集的区间长度比推向 1。

## 设计（与 A 臂唯一差别 = loss 加权）
- 起点：与 A/B 相同（uniform-12000 借权重续训，projector 1e-5 / lora 2.5e-5，600 步、cycle 300、save 100）；
- 开关：`training.loss_weighting = {enabled: true, long_sec: 1.0, weight: 3.0}`（权重只落在标注时长 ≥1.0 s 字符的**两个槽位**）；
- 验证 loss 不加权 ⇒ 与 A 臂的 val 曲线仍可比；
- 对照：**A（同数据、不加权）**。C vs A 就是加权净效应。

## 主指标（预先指定，只有一个）
**验证集 ≥1s 长字符的超 0.2s 率**，用逐字符**配对**（C vs A，同一批 950 个长字符）：
- 功效：σ≈162 ms ⇒ 配对 SE≈5.3 ms，z≥2 可检约 ±10.5 ms 的均值改善；
- 判定：配对均值差 ≤ −10 ms 且 z ≤ −2 ⇒ H-C 成立；|z| < 2 ⇒ 写负结果；差为正 ⇒ 加权有害，立即停止这条线。

## 次要指标与机制检查（不参与判决）
1. 失败子集区间长度比是否向 1 收敛（≥2s 桶基线 0.709）——这是**机制是否被命中**的直接证据；
2. 短字符桶（0–0.25s / 0.25–0.5s）超差率**不得恶化**超过 +0.3pp（加权会挤占容量，这是主要风险）；
3. 长流视图（`eval_long_context_view.py`，五判据）与 L1/L2/L3 曲线；
4. DP 解码在 C 上是否仍给出同样的 +0.4~0.9pp（应当是，因为两者正交）。

## 停止规则与预算
- 600 步 ≈ 45 分 + 漏斗评估 ≈ 15 分，**总预算 ≤ 1.2 小时 GPU**；
- 若 A/B/C 三臂全部落空 ⇒ **不再继续堆训练类干预**，转向结构改动（把时间戳头从"绝对起止 bin"改为"起始 + 时长"的参数化，或引入相邻字符共享边界的联合解码约束），那需要新的工程预算与一次独立立项；
- 磁盘门禁 ≥15G；不并发两个 GPU 训练；不删任何既有产物。

## 启动条件（写死，不临场判断）
- **B 臂 null 或明显弱于 §3g 预测带**（说明条目级复制强度不够，而非机制错误）⇒ 启动 C；
- B 臂落在预测带内 ⇒ 暴露机制成立，C 作为"把效应推更大"的可选后续，视剩余时间决定；
- B 臂**变差** ⇒ 暴露假设被否证，**C 不启动**，直接进入结构改动的立项评估。

## 5. C 的**预期形状**（09:14 登记，早于 C 的任何结果；来自 B 的按时长计数表）
B 的逐字符计数（同一批 6,415 个留出字符，只数结束点侧）显示：
收益只出现在 ≥1.5 s 段（新修好 9 / 新弄坏 0），代价只出现在最短段（新修好 0 / 新弄坏 4）。
C 与 B 的唯一区别是"改 loss 而不复制条目"，因此**形状预测**为：

1. **最短段（0–0.5s）不应出现 B 那 4 个新弄坏** —— 因为 C 不改变每个条目被看到的次数；
   若 C 也在最短段弄坏字符，说明加权确实在挤占短字符容量（这是 C 的主要风险，事先就写在设计上）；
2. **≥1.5 s 段的收益应保持**（新修好 > 新弄坏），且不应伴随短条目视图的 −0.3 pp 级别退步；
3. 两件事**必须同时成立**才算 C 成功；只满足第 2 条 = 与 B 同型（有代价的改善），
   只满足第 1 条 = 无收益（等于什么都没做）。

这条预测是**可 falsify 的形状断言**，不是"希望变好"；判决时由 `arms_by_bucket` 计数表直接核对。
