## 1. 最值得先做，但**不用 GPU**：把长音失败的个案挖出来
- 今晚的硬事实：长音失败是**个体性**的（全局/选择性时长校准都无效；多数字符的时长本来就对，中位误差 0 ms）。
- 所以真正缺的是**"哪 6% 的长字会错、错成什么样"的定性画像**：
  把 ≥1.5s 且错的字（域内 ~50 个）逐条听 + 看频谱，分类（延音收尾？转音多音字？气声/假声尾？响度陡降？）。
- **已排除的一种解释（21:13）**：失败不集中在特定歌或歌手（散在 13 首歌 / 11 位歌手，
  按 ×13 校正后无一组显著）⇒ 画像要按**声学特征**分类，不要按歌曲/歌手归因。
- 成本：1–2 小时人工，无 GPU。产出：若失败集中在 1–2 类可命名的声学情形，
  就能设计针对性特征/数据；若是弥散的，则承认这是底座能力上限，**把长音精度目标降级**并只做复核兜底。
- **这是我今晚强烈建议的一个**：它决定后面所有预算往哪投，而它几乎免费。

## 2. 结构改动（改网络）——今晚证据指向但代价最高
- 支持点：所有"重新分配监督"的做法（改采样、改权重、换问法）全部不划算；时长信息"不在现有表示里"。
- 但注意：换问法那条已被干净否证（对照臂保持基线时它全面更差），
  **失败原因可能正是"表示里没有"，而不是"问法不对"** ⇒ 光换输出层不解决表示问题。
- 真要改表示，最小可信做法不是加输入词表，而是：
  **给结束点单独一路解码头，条件在"该字的起始点 + 更长的右侧上下文"**（今晚否证的是换目标，不是加上下文）。
- 成本：实现 + 训练 ≈ 1.5–2 天，且需要一次与对照同等的同步数比较（又一次 7.5 h GPU 起）。
- 停止规则建议：若 §1 的个案画像显示失败与"右侧上下文不足"无关，**就不该做这件事**。
