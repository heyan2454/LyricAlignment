## 1. 排序原则

按 **(决策价值 × 9 小时内可完成度) / (GPU 成本 + 风险)** 排。两条硬约束：
① 单卡串行，任何时刻只允许一个 GPU 进程；② 全程无人值守 ⇒ 每步都要有哨兵/日志/磁盘守卫，且**不做不可逆操作**。

## 2. 任务清单

### A. 夜班 0：收尾与冻结（00:55–01:15，CPU + GPU ~20min）
- 训练退出后：跑 `run_funnel_topup.py`（新 run 的 L1 领先者 → L2 → L3），产出**最终候选**；
- 用 `analyze_val_trend.py` 复算全平台趋势（150+ 点），把"重训到底值不值"写成结论；
- 冻结"最终选点" = 新 run 1SE 选点 + 旧 r2/750 对照，写入 `results/by_run/20260913_final_selection/`。

### B. 困难子集口径冻结 + 子集指标实现（CPU，60–90min）★最高优先级（无需 GPU）
- 动机：整体指标饱和，**唯一还有动态范围的地方是困难子集**；没有它，后面所有比较都还是噪声。
- 子集定义（**先冻结再算，禁止事后挑样本**）：`duration ≥ 1.0s`（长音符）/ 乐句末字 / 前有 ≥0.3s 静音的字，三者分别报告，不要合并。
- 实现：`scale_metrics` 增加 `subset=` 参数（按 reference 的时长/位置过滤），输出同样的命中率+分位数；
  `evaluate_variants` 同时输出全量 + 三个子集；单测覆盖"子集是 reference 的属性、不受预测影响"（防作弊）。
- 产物：`docs/status/20260913_hard_subset_metric.md`（口径冻结记录）+ 代码 + 测试。

### C. 复评 v2：最终候选 × 全量/子集（GPU 60–90min）
- 对 A 冻结的候选（预计 3 个新 ckpt + 旧 r2/750、1110）在**全量 + 困难子集**上重评，
  同时输出误差分位数与可用率；
- 目的：给出**有分辨力的**最终选点，并回答"重训是否改善了困难子集"（整体饱和可能掩盖子集提升）。
- 停止规则：若新 ckpt 在困难子集上的配对差 |z|<2 且方向不一致 ⇒ 明确写"重训无收益，上线不换 ckpt"。

### D. 跨域复算：修复到底是不是普适（**CPU-only，可立刻开始**）★
- 已发现现成产物：`runs/20260816_evaluation_v1_gtsinger_rawdec_all/`（4,575 个 per-item JSON，含
  `alignment.raw.json`），以及 `runs/20260724_qwen_fa_r2_full_seed20260724_mir1k_ood/predictions.jsonl`。
- 做法：从既有 raw 产物重算 `fixed / raw / raw+定向修复` 三判据 + 结构指标（零长度、倒序、重叠），
  **按域分别报告**（GTSinger 录音室 vs MIR-1K 真实混音）。
- 为什么重要：runbook 明说"精度收益只有 GTSinger 有对照，真歌批只有结构证据"；
  这一步把"是否全批上线"从"建议"变成"有域外证据的决定"。
- 成本：纯 CPU 复算，不占 GPU，可与训练/其他任务并行。

### E. 上线通道打通：把策略接进批量写入（CPU 60min）
- 现状（grep 实证）：`--fixed-timestamp-policy` 只在 `scripts/demo/align_qwen_fa_serial_demo.py`；
  `run_qwen_fa_batch.py` **未接线**（只有 `run_shadow_batch_audit.py` 用到了策略）。
- 做法：批量写入侧调用 `monotone_repair.apply_fixed_timestamp_policy_rows(..., policy=...)`，
  默认仍是 `upstream_repaired`（逐位不变，contract test 守着）；给出批次级开关与 audit 记录字段。
- 验收：跑一个小批次 → `scripts/evaluation/audit_batch.py`：`collapse_blocks.blocks == 0`、
  `zero_share ≈ 0`、无新违规类别。

### F. 伪标签 pilot（GPU 2–3h，**只做 pilot 不做全量**）
- 依据：inventory §4C——`audio_works_202604` 是除授权外唯一的加数据路径，且**必须 raw+定向修复**；
  用现行上游输出去造标签会把 16% 的塌陷学成真理。
- pilot：抽 100–200 首 → raw 解码 + 定向修复 → 结构合法性 + 置信度双重过滤 → 统计**产出率**；
- 产物：`docs/status/20260914_pseudo_label_pilot.md`（产出率、被过滤原因分布、放量所需 GPU/存储预算）；
- 停止规则：产出率 <50% 或结构非法率 >5% ⇒ 判为"不可用作训练数据"，写负结果并关闭这条路径。

### G. 明早汇总（30min）
- 一份 `docs/status/20260914_overnight_report.md`：做了什么、结论、还缺什么、建议的下一步（含"不做"的理由）。

## 3. 明确不做（附理由）

| 不做 | 理由 |
|---|---|
| soft-label 第二臂 | 前提是"训练是瓶颈"；现在证据相反。9 小时 GPU 花在这里的信息价值低于 C/D |
| 继续加练到 24k 步 | 实测 +0.208pp/1000 步，9 小时约 +0.8pp，且已被 21.6 epoch 的过拟合风险覆盖 |
| 用 test 集选 checkpoint | 违反项目纪律（"checkpoint 只许 validation 选择"） |
| 全量伪标签（101GB） | 9 小时不够；且未验证产出率就放量违背"先 pilot" |
| 清理任何既有 run 目录 | 硬约束：禁止删除过去内容；磁盘还没到 floor |

## 4. 编排与安全

- 所有 GPU 阶段：`setsid nohup` 分离 + 日志写 `runs/_launch_logs/` + 完成哨兵；单卡串行；
- 每阶段前后检查 `df`（floor 20G），低于 floor 则跳过并把原因写进报告；
- 30 分钟巡检提醒改为查**夜班流水线**状态（训练已退出，不再查训练）；
- 复核点：B 完成后先看子集指标是否真的有动态范围（若子集上也饱和，立即停止 C 并改写结论）。
