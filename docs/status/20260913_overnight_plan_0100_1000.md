## 0. 为什么重想：现在的瓶颈不在训练，在三件"理解"上的事

今天已经证伪了"多训练有用"（12000 步 vs 旧 run 统计上无差别）。剩下的误差有三个可能来源，而它们
指向完全不同的解法：

| 来源 | 若成立，意味着 | 目前证据 |
|---|---|---|
| **① 标签约定**：长音符内的字符边界是人为约定，不是声学事件 | 现在的指标在**惩罚正确行为**；该改的是标签定义与评测口径，不是模型 | 长音符 20.5% 的 GT 不在模型前 2 候选里；但这些"错"的预测是否落在真实声学事件上，**从未检验过** |
| **② 解码**：逐字 argmax + 事后修补丢掉了全局一致性 | 该改的是解码器；可同时消灭塌陷并改善长音符 | 上游 `_fix_timestamps` 常数填充导致真歌批 16.28% 零长度；我们的定向修补只治表面 |
| **③ 模型**：声学表示本身不足 | 才需要数据/结构改动 | 目前**没有**排除①②的证据 |

九小时全部投在这三件事上——因为**只有排除①②之后，才有资格说③**。

## 1. Track 1（核心）：长音符的天花板是标签问题还是模型问题？

**假设 H1**：长音符内的字符边界缺乏声学证据，M4Singer 的字符级 GT 在长音符上只是"把音符均分/按规则
切分"的约定；模型预测落在真正的声学变化点上，因此被指标判为错。

**最小实验（全部可离线，CPU 为主）**
1. **独立标注对照**：把我们的派生标签（`derived/.../m4singer_qwen_fa_labels.jsonl`）与 M4Singer 原始
   `NNNN.TextGrid`（Praat，字符层 + 音素层）逐项比对，量化"派生规则在长音符上移动了多少边界、多大幅度"。
   —— 若派生标签与原始标注一致，则问题不在派生；若不一致，先修派生。
2. **声学证据检验**：对长音符（≥1.0s）在 GT 边界与模型预测边界两侧各 200ms 计算声学变化强度
   （能量导数、谱通量、基频滑动），统计"边界落在强变化点"的比例。
   —— 预测 **H1-if-true**：预测边界处的声学变化显著强于 GT 边界处。
3. **歧义度画像**：模型在 GT 桶上的概率质量、分布熵、以及 GT 落在 top-k 的 oracle 曲线（k=1..50），
   全部按音符时长分桶。把"20.5% 不在 top-2"拆成"任务歧义（多峰且峰都在合理位置）/ 模型错（单峰但错）"。

**可证伪点**：若 GT 边界处的声学变化强度与预测边界处无显著差异，或 GT 几乎总在 top-1，则 H1 不成立，
天花板归因于模型（③），Track 1 立即收口并写负结果。

**产物**：`docs/status/20260914_long_note_ambiguity.md` + `results/by_run/20260914_long_note_ambiguity/metrics.json`；
**口径副产品**：可容许边界评测（admissible-boundary）定义，作为 Track 3 的输入。

## 2. Track 2（方法创新）：约束式全局解码替代事后修补

**假设 H2**：把逐字 argmax + 事后块修补，换成在模型 logits 上做**单调 + 最短时长（≥1 格）+ 可选锚点**
的全局 DP/Viterbi，能同时在结构（零长度→0）与精度（长音符联合更优）上超过现有三条基线。

**为什么这是真问题**：现有 `raw_with_targeted_repair` 只是把"已经被上游抹平"的块重新摊开——它**没有
利用模型对后续字符的不确定性**；而逐字 argmax 在每个字符上独立取峰，天然会产生"前一个字符占了后一个
字符的时间"这类全局不自洽。DP 用全局一致性换更优解，是这类任务的正确解法。

**最小实验**
- 从 `output.logits` 取每个字符 `<timestamp>` 槽的分布（我们已有 `argmax_character_predictions` 的取槽逻辑）；
- DP：状态 = (字符序号, 时间桶)，转移要求严格单调、相邻间隔 ≥1 格；可选加"长音符内部允许平段"的锚点项；
- 在同口径下与 `fixed` / `raw` / `raw_with_targeted_repair` 比：命中率(0.1/0.2s)、MAE、误差分位数、
  零长度率、最长平段、**以及 DP 自己的目标函数值**（用来判断"更优解"是不是真的更优）。

**可证伪点**：若 DP 解的目标函数值 ≤ argmax 解（说明约束没有增加信息），或命中率不升，则 H2 不成立。

**成本**：一次前向（GPU 30–40min，可复用 Track 1 的产物）+ 纯 CPU 解算（秒级）。这是本次最"可发表"的一项。

## 3. Track 3（评测与产品）：任务歧义 + 弃权

- **可容许边界评测**：以 TextGrid 的音符/音素区间集合作为可容许集合，报告"命中任一容许边界"的比例，
  与现行单点 GT 口径并列。给出两者的差值 = **被约定惩罚的量**。
- **不确定性校准 / 弃权曲线**：置信度（分布熵、top1-top2 间隔、结构合法性）↔ 真实误差的
  阈值-准确率-产出率曲线；直接对应仓库 `05_NEXT_ACTIONS` 第 5 条的产品化 gate（该拒答时拒答）。
- 若 Track 1 支持 H1，这一节就是论文里的"评测贡献"部分。
